# 资料采集与来源标记

## 1. 输入清单

先隔离本轮资料上下文：新提供的一组语雀、MasterGo 和用户补充构成一个新的需求身份候选，不继承上一组资料的需求名称、阶段和编号前缀。身份字段只能引用本轮用户输入或本轮来源；来源未明确阶段时记录为“未分期”。

先建立材料表，再解释需求。每份资料分配稳定编号：

- `DOC-01`、`DOC-02`：语雀文档或子文档。
- `UI-01`、`UI-02`：MasterGo 根图层、页面或明确分区。
- `IMG-01`、`IMG-02`：用户提供的原图或截图。
- `USER-01`、`USER-02`：用户在会话中的明确补充。

资料索引至少记录：编号、类型、标题、原始 URL 或路径、获取时间、版本或更新时间、读取范围、读取状态和限制。

## 2. 语雀读取

调用前按 [MCP 工具能力解析](tool-resolution.md) 查找当前环境中的工具，不绑定服务器命名空间。

1. 对每个根 URL 调用大纲接口，识别标题、章节、表格和资源数量。
2. 根文档可能包含相关子文档时，调用文档包接口，默认读取根文档和深度 2 内的子文档，并开启 Markdown、表格和资源链接。
3. 文档被截断时，按子文档或章节继续读取，不以截断文本生成正式需求。
4. 保存规范化 Markdown 快照；保留原始标题层级、表格和链接。
5. 在需求来源中引用文档编号和标题路径，例如 `DOC-02「权限设置 > 角色范围」`。

不要把目录中明显无关的会议纪要、开发日志或历史归档自动纳入需求；把可能相关但无法判断的文档列为候选资料。

## 3. MasterGo 读取

1. 先获取 section 列表和根元数据，记录 `totalSections`、每个 section 的 `sectionIndex`、节点数、文本预览和边界框。
2. 按索引读取全部 section；每批并发 3–5 个请求，维护完成清单。
3. 使用 `tree` 或 `yaml` 降低大型设计的上下文占用；需要精确属性时对相关 section 使用 `json` 复读。
4. 记录页面、弹窗、抽屉、字段、按钮、文案、组件状态、变体和空间归属。
5. 不执行 MasterGo 返回的代码生成步骤；本任务只分析需求。
6. 分区读取失败时重试；主接口不可用时才调用完整 DSL 回退接口，并记录可能的截断风险。
7. 按 [UI 上下文缓存与交接](ui-context-handoff.md) 在每个分区返回后立即保存完整机器数据；业务摘要和原始缓存必须同时存在。

MasterGo 页面名称不能自动视为 UC。只能把设计节点关联到来源已明确的 UC 或单体需求模块。

## 4. 原图和视觉限制

- 有原图时，先看全局关系，再看局部细节；保留原图路径或链接。
- DSL 能确认文本、结构、尺寸、位置和组件变体，但不能等同于原始视觉图。
- 没有原图时，在 `_sources/资料索引.md` 和 `00-需求引导.md` 写明：`本次仅基于 MasterGo DSL 分析，未核对原始渲染图。`
- 不根据颜色、图标或装饰推断业务规则；只有来源明确表达状态含义时才记录。

## 5. 快照与刷新

将规范化资料存放在 `_sources/`，文件名以来源编号开头。刷新远端资料时：

1. 重新获取来源。
2. 与已有快照比较标题、正文、表格、节点文本和关键状态。
3. 列出新增、删除和变更。
4. 用户已确认内容与远端变化冲突时保留用户确认，并新增来源冲突项。
5. 用户确认后才更新正式需求；随后替换快照并记录刷新时间。
